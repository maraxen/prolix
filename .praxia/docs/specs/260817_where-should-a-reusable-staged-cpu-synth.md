- [REJECT] S2 — A-first: build xtrax.profiling as the substrate before any prolix probe: Puts a cross-repo PR + alpha release cycle directly on the critical path of a live blocker (RR5 ratio=0.1016). Worse, it is premature generalisation: we do not yet know the shape of the profiling API because we have not run the loop once. xtrax's genuine reusable surface can only be identified after the API survives real use. This also answers open question 1 — the xtrax cost-estimator empirical-calibration gap is proximity-pulled roadmap creep; Stage 0 cost_analysis() is explicitly disqualified from cross-platform magnitude claims by the frame's fixed constraint 1, so calibrating it cannot serve the DHFR bottleneck question.
- [REJECT] S4 — C-first: new bathos profiling/discovery experiment-type on the critical path: Same critical-path objection as S2, plus it requires renegotiating bathos gate semantics, which the frame fixes as non-negotiable (fixed constraint 3). The cross-project benefit is real but speculative, and S9 shows the motivating gap is not actually a bathos deficiency: discovery was never in bathos's remit. Building a discovery mode would encode a category error into a tool used by every bathos-tracked project.
- [REJECT] S1 — B-only, deliberately disposable (no skill, no bathos, no upstream seam): Ships fastest and correctly identifies that the bottleneck, not the methodology, is the goal — but it violates the success criterion that any measurement cited in the engine paper retains provenance. RR5-derived optimisation claims are paper-bound. Disposability is also empirically wrong for this repo: the profile_b1_* scripts from the B1 campaign are still in use months later. Nothing here is actually disposable.
- [MERGE] S6 — skip Stage 0/1 for this hunt; go straight to Stage 2: Partially correct and worth absorbing rather than adopting whole. Correct: Stage 0/1 cannot rank PME vs nonbonded, so gating the GPU hunt behind them is ceremony, and Stage 2 is the first stage that can answer the RR5 question. Incorrect: Stage 1 is sound for bonded/SETTLE relative cost and for dispatch-count/retracing bugs, which are cheap, plausible contributors to a 10x gap and are free to check locally. Absorbed as: Stage 0/1 run in PARALLEL with Stage 2 setup, never as a blocking gate on it, and their durable role is regression tripwire, not discovery gate.
- [MERGE] S5 — instrumentation-first (named_scope coverage as the real Phase 1); and open question 4: Answers open question 4 with a qualified yes. named_scope coverage in flash_explicit.py / batched_energy.py is required by every architecture option and lives in prolix source regardless of where the harness lands, so it is a genuine Phase-1 prerequisite for any TERM-ATTRIBUTION claim. But S5's stronger form — defer the architecture decision until traces exist — is rejected: instrumentation and harness scaffolding are independent workstreams and serialising them wastes the cheapest parallelism available. Absorbed with a required validity check the user raised: after adding scopes, verify total step time is unchanged within noise, since scopes can perturb fusion in a fused scan/tile-reduction hot path. If they do perturb it, fall back to trace-level attribution without scope insertion.
- [ACCEPT] S7 — stage-validity measurement contract, machine-checkable rather than prose: Directly mitigates the leading candidate's named failure mode (skill/harness prose drift). The load-bearing rule — no term-ranking claim below Stage 2 — is exactly the rule prose cannot enforce, so it must be encoded in the probe output itself: every probe emits a record stamped with stage and permitted claim classes, and the analysis/report step refuses to emit a term-ranking conclusion from a sub-Stage-2 record. Cheap (a field plus an assert), and it is the seam most likely to be worth upstreaming to xtrax later.
- [ACCEPT] S9 — two-loop separation (ungated discovery loop / pre-registered bathos confirmation loop); open question 3: Answers open question 3: bathos's iterative-discovery gap does NOT block Phase 2, because discovery should not be in bathos at all. Discovery probes live in scripts/explore/ (the project's own documented escape hatch, ungated by design). Each hypothesis that survives discovery is promoted to exactly one pre-registered bathos experiment in scripts/experiments/ with a real anchored threshold. This preserves provenance for every paper-citable number without touching gate semantics, and it is consistent with existing project discipline that wanting to bypass the gate is a signal the work belongs in scripts/explore/.
- [ACCEPT] S8 — trigger-conditional xtrax upstream (xtrax-shaped seam now, upstream on a named trigger); open question 2: Answers open question 2: B ships first, upstream later. The seam discipline (core module takes trace/cost records and emits stage-stamped findings, with no prolix imports) costs almost nothing now and converts the later upstream from a rewrite into a move. Trigger is named rather than vague: upstream to xtrax.profiling when a second consumer repo asks for it, OR when the API survives two complete bottleneck-hunt loops without a breaking change. Absent a trigger, upstreaming is explicitly declined, not silently pending.
- [ACCEPT] Pre-mortem amendment: stage contract must also carry SCALE validity, not just platform-stage validity: Pre-mortem story 2 exposed a genuine defect in the winner as first stated. The stage axis guards CPU-vs-GPU claim validity (roofline), but silently assumed scale rides along with platform. It does not: dense OOMs at DHFR scale, so the few-thousand-atom 1VII/2GB1 probe sits in a qualitatively different memory regime from the target. Consequence for the rollout: Stage 2 conclusions are hypothesis-generating for Stage 3, never load-bearing for a DHFR-scale claim on their own, and a mid-scale rung may be needed if the 1VII-to-DHFR span exceeds that ratio.
- [ACCEPT] INVEST 'S' (Small) — spec scope narrowed to Phase 1 only, with Phases 2-3 as sequenced follow-on specs: The full three-phase rollout fails INVEST-Small: it spans a skill, a core module, source instrumentation, GPU campaign runs, and bathos experiments — far more than one user-facing feature or 8 acceptance criteria. Resolved by narrowing rather than overriding: the committed spec covers Phase 1 only (1a named_scope coverage + perturbation check, 1b scripts/profiling/ core module with stage+n_atoms stamped record and claim-class assert, 1c Stage 0/1 CPU probes in scripts/explore/, plus the skill capturing the staged procedure). Phases 2 and 3 are recorded as sequenced follow-on specs with their entry conditions stated, not as in-scope work. This also hedges pre-mortem story 1 (over-build): if Phase 2 finds the bottleneck immediately, only Phase 1's small surface was built speculatively.
