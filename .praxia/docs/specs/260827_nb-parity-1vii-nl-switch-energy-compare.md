## Root cause of the stub
`_compare_probe`'s `1vii` branch was never a bug — its own comment says the gold was "vendored for later EnsemblePlan/NL compare." The reason it stayed a stub past #4382's completion is that **no function in the codebase produces a nonbonded-only energy from a bundle**: `energy_fn_from_bundle(include_nonbonded=False)` returns *only* bonded, and `include_nonbonded=True` (the default) returns bonded+nonbonded *combined* — neither matches gold's ForceGroup-0-only decomposition. The sprint TOML's own Track A2 fixer_prompt ("Evaluate `energy_fn_from_bundle(..., lj_switch_width=1.0)`... Fill the `gate_pass`... fields") does not name this gap and, read literally, would compare gold's nonbonded-only energy against Prolix's bonded+nonbonded total — a real 1vii-scale bonded contribution (bond/angle/dihedral/CMAP energy for a 35-residue folded protein) would then show up as false ΔE far outside the `0.1` kcal/mol band, misdiagnosing the NL/switch wiring as broken when it is the comparison itself that is malformed. This spec exists specifically to correct that before a fixer is dispatched.

A second, smaller gap: the vendored gold has no bonded or exclusion topology at all (only per-atom nonbonded params + positions + box), so even a topology-aware nonbonded-only extraction has no exclusion data to consume without either re-solvating (ordering risk, rejected above) or extending the gold. This spec locks the latter.
